# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A WordPress → Next.js 15 conversion of maintain.com.au (Maintain Technology), built
from the WXR export `maintaintechnology.WordPress.2026-08-11.xml`. No WordPress at
runtime — every page prerenders statically from JSON extracted out of the XML.
`README.md` documents the conversion in depth; `DESIGN.md` documents the design
system and motion language. Read both before substantive work.

## Commands

```bash
npm run dev                        # dev server (pass -- -p <port> if 3000 is taken)
npm run build                      # production build (all routes prerender)
node scripts/check.mjs             # 26 unit checks: parser, dynamic tags, visibility, forms

# parity verification against the captured live site (reference/html)
npx next start -p 3100             # structural/height diff expect port 3100
node scripts/structural-diff.mjs   # DOM/text parity, all 22 routes (fast, offline)
node scripts/height-diff.mjs / /   # per-element layout diff vs live
node scripts/compare.mjs           # full-page screenshot diff (slow, ~15 min)

node scripts/verify-effects.mjs [baseURL]   # Playwright: animations, popup, sticky,
                                            # circle scrub, per-route error sweep

# content pipeline (only when the WXR export or live assets change), in order:
npm run extract                        # WXR -> content/*.json (offline, deterministic)
npm run assets                         # media + live stylesheets + reference HTML
node scripts/build-image-manifest.mjs  # responsive variants -> content/images.json
node scripts/build-css.mjs             # -> public/styles/site.css
```

There is no lint or test-framework setup; `scripts/check.mjs` is the unit suite and
Playwright scripts are the integration layer. Playwright is a devDependency and its
Chromium browser is already installed.

## Architecture

The pipeline is: **WXR XML → `content/*.json` (source of truth) → React renderer →
static routes.**

- `content/pages.json`, `templates.json`, `components.json` hold Elementor layout
  trees (the `_elementor_data` JSON). `case-studies.json`, `posts.json`,
  `newsletters.json` are the CPT content. `site.json` has design tokens, fonts,
  nav, options. All regenerated by `scripts/extract.mjs` — **edit the extractor,
  not the JSON**, if extraction is wrong.
- `src/lib/elementor/render.jsx` walks a layout tree and emits the exact class/
  attribute shapes the live site's generated CSS keys on. `props.js` resolves
  JetEngine dynamic tags (`[elementor-tag …]`), component props, and Dynamic
  Visibility (`jedv_*`). Widget markup was matched byte-for-byte against
  `reference/html/` — treat that as the contract; `structural-diff.mjs` enforces it.
- `public/styles/site.css` is **generated** by `scripts/build-css.mjs` (live
  Elementor CSS, brace-balanced, concatenated, with `src/styles/app.css` appended
  last). Never edit `site.css` directly — edit `src/styles/app.css` and re-run
  `node scripts/build-css.mjs`.
- `src/components/Effects.jsx` is the native replacement for jQuery + GSAP +
  ScrollTrigger + SplitType + Elementor Pro JS: sticky header, side-menu popup,
  split-text reveal library, the home-page circle scroll scrub, and card/image
  scroll reveals. Animation CSS states live in `app.css`. See DESIGN.md for the
  motion rules.
- Forms are React (`src/components/Form.jsx`) + `/api/forms`. Every form on the
  site posts to that one route, so it is the only place delivery is wired.
  Delivery is Resend (`src/lib/email.js`) when `RESEND_API_KEY` is set, plus an
  optional `FORM_WEBHOOK_URL`; with neither, submissions are server-logged. A
  submission counts as failed only when every configured channel fails.

## Non-obvious constraints (each one cost a debugging session)

- **Elementor `_attributes` must reach the DOM.** Animation hooks (`text-split`,
  `words-slide-up`, `data-index`, …) are stored in the `_attributes` setting
  (`key|value` per line) and emitted by `customAttrs()` in render.jsx. Dropping
  them silently kills every text effect.
- **`position: sticky` dies inside `overflow: hidden` ancestors.** Elementor marks
  page containers `--overflow:hidden`. Effects.jsx heals the ancestor chain of the
  circle section to `overflow: clip` at runtime; keep that pattern for any new
  pinned section.
- **The Master CTA snippet owns `transition` on `.elementor-button` anchors** (at
  hover-state specificity, `all .3s`). Motion transforms go on
  `.elementor-button-wrapper` instead — never fight that cascade on the anchor.
- **Animation initial states are gated behind `html.js`** (class added by an
  inline head script in `layout.jsx`; `suppressHydrationWarning` on `<html>`
  exists because of it). Any new "hidden until revealed" CSS must sit under
  `html.js` so content is never lost without JS.
- **`.pretty` is a marker class with no styling.** Do not animate it — that hides
  ~54 elements per page. The real animation targets are the `_attributes` hooks.
- **The popup opens via a dynamic-tag link resolving to `#popup-141`** (Elementor
  popup action); popup *close* tags carry `action: "close"` and resolve to
  `#popup-close`. Trigger/closer selectors live in Effects.jsx. Elementor's base
  CSS hides `[data-elementor-type="popup"]` at (0,2,0) specificity — app.css
  requalifies the drawer's `display:flex`; don't weaken that selector.
- **Known 404s that are broken on the live site too** (not regressions):
  `2025/07/phone-bold-1.svg`. (`HoE_bg-1024x687.jpg` also 404s live, but a
  locally generated variant now ships in `public/assets` so the Humans of ERP
  background renders; regenerate from `HoE_bg.jpg` with sharp if it's lost.)
- **JetEngine component instances print their dynamic background per instance**:
  `componentInstanceCss()` in render.jsx emits the inline `<style>` that gives
  the industry cards their `card_background_image`. Dropping it makes every
  card background silently vanish (the CSS files never contain these rules).
- **`jet-options-page` values are hard-coded** in `scripts/extract.mjs` under
  `OPTIONS` (contact email, phone, address, LinkedIn, booking link) because WXR
  doesn't include `wp_options`. Edit them there.

## Verifying UI work

Any change touching rendering or motion: run `node scripts/verify-effects.mjs`
(dev server must be running; pass the base URL if not `http://localhost:3210`),
then `node scripts/check.mjs`, and `structural-diff.mjs` if markup shape changed.
Screenshots land in the scratchpad path printed by the script. The parity budget
is the README baseline: ~99.8% text recall, 0 missing element ids.
